01概述与目标

用一条完整的“客户 → 拜访 → 订单 → 流向 → 业绩”链路，验证医药营销团队日常协作在网页端可以闭环完成。

1.1 背景与问题

观察到的现状：医药销售团队的客户档案、拜访记录、销售订单、商业流向和业绩目标通常散落在 Excel、聊天记录与多个系统中。代表在客户现场无法快速调取历史拜访与产品信息，地区经理难以及时掌握团队过程数据，商务运营需要反复手工汇总流向。

受影响的人与时刻：医药代表在客户拜访前后、地区经理在每周例会前、商务运营在月度流向汇总时。

产品决策：建设一个以“客户”为核心对象、以“拜访”为过程抓手、以“订单与流向”为结果数据的医药 CRM，并把审批、权限、统计放在同一套数据口径下。

可观察的结果：代表从新建客户开始，可在网页上完成拜访计划、签到、记录提交；经理在同一页面完成审批；订单发货、回款后业绩自动进入工作台与报表；商务可上传流向文件并立即看到分析结果；管理员可一键恢复演示数据。

1.2 产品定位

对代表

一个“今天该做什么、客户发生了什么”的随身工作台，减少重复填报。

对经理

一个可审、可看、可追的过程管理视图，审批与业绩一屏掌握。

对运营

一个统一的订单、流向与主数据入口，替代手工汇总。

1.3 目标（以可观察行为描述）

  • 新测试者无需阅读代码或使用数据库工具，仅通过网页即可完成“建档 → 拜访 → 审批 → 下单 → 发货 → 回款”的主链路。
  • 代表只能看到自己负责的客户与业务数据；地区经理只能看到本区域；越权访问返回明确的“无权限”提示而不是空白页。
  • 拜访与订单被驳回后，提交人能看到驳回原因、修改并重新提交，已填写的内容不丢失。
  • 商务上传流向文件后，系统给出“成功 / 覆盖 / 失败”的明确结果，并能在看板与报表中看到变化。
  • 管理员执行“重置演示数据”后，系统恢复到统一的初始状态，所有账号可再次按同一脚本自测。

1.4 演示边界

演示环境声明：系统定位为本地演示与能力验证，不接入真实医院、商业公司、支付、短信、地图或税务系统。签到使用“演示定位”，不调用浏览器真实定位权限，保证任何机器上都能稳定自测。

2.4 数据权限规则

  • 代表范围：客户负责人为本人，或拜访/订单由本人创建且客户负责人已转交时，仍保留历史单据可见性（只读）。
  • 经理范围：客户所属区域等于经理区域；跨区域数据在列表、详情、导出与统计中均不可见。
  • 越权访问：通过 URL 直接访问无权对象时，返回统一的无权限页（403），不泄露对象名称与金额。
  • 操作校验：前端隐藏无权按钮，后端再次校验；任何绕过前端的数据修改请求均被拒绝并记录审计。

04核心业务流程

三条主链路构成 P0 的完整闭环。所有状态、金额与统计口径在后续功能章节中只定义一次，其他模块引用本章。

4.1 客户到拜访闭环

01新建客户代表建档，选择医院/药店/商业公司，系统生成客户编码
→
02添加联系人设置主要联系人，记录职务与角色
→
03拜访计划选择客户、日期、目的，进入“计划中”
→
04签到拜访当日演示签到，记录时间与距离
→
05提交记录填写结果、反馈、下一步与产品
→
06经理审批通过或驳回；驳回必须填写原因

完成条件：拜访状态为“已通过”，客户详情出现该拜访记录，代表与经理工作台的拜访统计同步更新。

失败与恢复：驳回后代表可修改并重新提交；已签到但当天未提交的记录保留为“已签到”，次日可在详情中补交（计入实际提交日期）；计划当日未签到视为逾期，可改期或取消。

关键约束：同一客户同一天只允许一条未结束（计划中/已签到/待审批）的拜访；已通过记录不可编辑；代表不能审批自己的记录。

4.2 订单到回款

01创建订单选择合作中客户与在售产品，录入数量与折扣
→
02提交审批订单进入“待审批”，金额锁定快照
→
03经理审批通过后进入“待发货”，驳回需填原因
→
04运营发货登记发货时间与物流单号，进入“已发货”
→
05回款登记可多次登记，累计不超过订单金额
→
06自动完成累计回款等于订单金额时自动“已完成”

完成条件：订单状态为“已完成”，回款合计等于订单含税金额，销售业绩按“已发货 + 已完成”计入。

失败与恢复：审批驳回后订单可编辑并重新提交；未发货前可取消；已发货或已有回款时禁止取消，避免产生负向资金记录。

金额口径：行金额 = 单价 × 数量 × (1 − 折扣率)，四舍五入保留 2 位；订单金额 = 所有行金额之和；单价取提交时的产品价格快照，后续改价不影响历史订单。

4.3 流向导入

01下载模板获取含示例行的 CSV 模板
→
02上传文件选择 UTF-8 CSV，≤ 2MB / 2000 行
→
03系统校验逐行校验主数据、月份、数量与金额
→
04预览确认展示前 20 行与错误清单，可取消
→
05确认导入正确行入库，错误行生成报告
→
06看板更新流向金额、数量、Top 排名与环比刷新
唯一口径：“商业公司 + 产品 + 月份”为一条流向记录的唯一键。重复导入同一键时覆盖原值，并计入本次批次的“覆盖”数量；批次可整体删除，删除后该键无记录。
可自测性要求：导入页面必须提供“下载示例文件（含 3 条错误行）”，测试者无需自备数据即可验证成功、覆盖、失败三类结果。

5.1 登录与工作台

对应页面：/login、/dashboard · 角色：全部

MVP 调整：工作台 KPI 固定为“本月销售额、活跃客户、本月拜访、待我处理”，不显示目标完成率；待办包含待审批拜访/订单与被驳回待修改。图表为近 6 个月销售额趋势与客户类型分布。

目的

让用户在一屏内知道“我是谁、我今天要做什么、我的结果如何”，并能快速进入待处理事项。

登录页

  • 左侧品牌区展示皓元医药 Logo、产品名与一句价值主张；右侧为账号密码表单。
  • 提供 5 个演示账号快捷按钮（管理员、华东经理、代表陈晨、运营周琳、华北代表赵磊），点击后自动填充账号与密码。
  • 校验：账号不存在、密码错误、账号被停用分别给出不同提示；连续 5 次失败锁定 10 分钟（演示环境保留该规则）。
  • 登录成功写入 JWT，有效期 8 小时；退出登录清除本地令牌并回到登录页。

  • 必填：客户（当前用户可见且非流失）、拜访日期（今天或未来 30 天内）、拜访目的（开发/维护/上量/学术推广/客情）。
  • 选填：联系人（限该客户联系人）、计划时间、同行人员、备注。
  • 保存后状态为“计划中”，生成拜访编号 VIS-YYYYMM-0001。

  • 签到仅在拜访日期当天可操作；点击“演示签到”后记录签到时间与“距客户地址 86 米（模拟）”，状态变为“已签到”。

  • 上传附件类型或大小不合规时前端即时提示，后端二次校验。

5.5 销售目标与业绩

目的

把月度指标落到“代表 × 产品”粒度，让代表与经理看到同一口径的完成进度，避免线下 Excel 对目标。

目标设置

  • 维度：月份（YYYY-MM）+ 代表 + 产品；三者唯一，重复设置视为修改。
  • 目标金额：整数元，1–99,999,999；支持批量导入？P0 为逐条新增与编辑，不做批量。
  • 地区经理只能为“本区域代表 + 全部产品”设置；管理员可为全部。
  • 当月目标在月末最后一天前可修改；修改后立即重算完成率，保留修改审计。
  • 支持复制上月目标到本月（一键生成，已有记录跳过并提示）。

业绩计算

销售额：订单归属代表在目标月份内、状态为“已发货”或“已完成”的订单金额合计。订单归属代表默认取客户负责人；运营代下单时仍归属客户负责人。

完成率：销售额 ÷ 目标金额 × 100%，保留 1 位小数；目标为空时显示“—”。

达成状态：≥ 100% 为“已达成”（绿），80%–99.9% 为“接近”（琥珀），< 80% 为“未达成”（灰）。

数据时点：以订单“发货时间”所在月份计入，不以创建时间或回款时间计入；跨月发货按发货月归属。

页面

  • 团队目标：经理/管理员查看区域或全量，支持按月份、代表、产品筛选；表格底部合计目标与销售额。
  • 排行：按销售额降序展示代表排名，显示完成率进度条；不展示未设置目标的代表完成率。

异常

  • 目标金额格式非法、月份早于 2025-01 或晚于当前月 + 12 个月时拒绝保存。
  • 代表尝试访问目标设置接口返回 403；经理设置跨区域代表目标返回 403。
  • 无目标但有销售额时，销售额照常展示，完成率显示“—”，并提示“未设置目标”。

5.6 订单管理

对应页面：/orders、/orders/new、/orders/:id · 角色：代表（创建）、经理（审批）、运营（发货/回款）、管理员（只读）

目的

用一个可审批、可履约、可回款的订单流程承接销售结果，并作为业绩统计的唯一来源。

创建订单

  • 客户：限“合作中”且当前用户可见；商业公司客户同样可下单。
  • 明细行：产品（在售）、数量（1–99,999 整数）、单价（默认产品单价，可改但需 ≥ 0.01）、折扣率（0–100%，最多 2 位小数）。
  • 至少 1 行、最多 20 行；同一产品不可重复添加，重复时合并数量并提示。
  • 选填：期望发货日期（今天起 1–90 天）、收货地址、备注（≤ 500 字）。
  • 保存草稿或直接提交审批；提交后生成订单号 SO-YYYYMM-0001。

金额规则

行金额 = round(单价 × 数量 × (1 − 折扣率 ÷ 100), 2)；订单金额 = 所有行金额之和；展示时千分位、两位小数。

订单提交时固化产品名称、规格与单价快照；历史订单不随产品改价变化。本系统不计算税额、运费与优惠券。

状态机

草稿→ 待审批→ 待发货→ 已发货→ 已完成 ｜ 已驳回→ 修改后重提
  • 草稿 → 待审批（提交）；待审批 → 待发货（经理通过）/ 已驳回（经理驳回）；已驳回 → 待审批（修改后重提）。
  • 待发货 → 已发货（运营登记物流单号与发货时间）；已发货 → 已完成（回款累计等于订单金额，或运营手动完成且已全额回款）。
  • 草稿、待审批、待发货可取消（需填原因）；已发货后不可取消；已有回款时不可取消。
  • 仅草稿可删除；其他状态只能取消。

审批、发货与回款

  • 经理只能审批本区域订单，且不能审批本人创建的订单。
  • 发货必填：物流公司、物流单号（6–30 位字母数字）、发货时间（不得晚于当前时间）。
  • 回款登记：回款日期、金额（0.01–订单未回款余额）、方式（电汇/承兑/现金/其他）、流水号、备注。
  • 累计回款不得超过订单金额；达到 100% 时订单自动变为“已完成”，并写入时间线。
  • 列表展示回款进度（已回款/应收），详情页展示回款明细。

列表与详情

  • 筛选：订单号/客户/代表关键词、状态、日期范围、区域（经理）。
  • 列表列：订单号、客户、代表、订单金额、已回款、状态、创建时间、操作。
  • 详情：订单信息、明细表、金额汇总、审批记录、物流信息、回款记录、时间线。
  • 时间线记录每次状态变化（操作人、时间、原因/单号）。

异常

  • 客户或产品已停用/流失时提交失败，提示具体对象；草稿可继续查看但不可提交。
  • 回款金额超过余额、日期晚于今天、物流单号重复时阻止提交。
  • 并发提交同一草稿时只允许一次成功，第二次提示“订单状态已变更，请刷新”。
  • 订单无权限查看时返回 403，不显示金额信息。

5.7 流向管理

对应页面：/flows、/flows/import、/flows/batches · 角色：运营（导入/查看/删批次）、经理/管理员（查看）、代表（无）

P1 · 本次不实现：MVP 导航中不出现流向管理；CSV 导入、批次与看板在 P1 实现，订单与拜访数据已为其预留商业公司客户类型。

目的

用可重复的 CSV 导入替代手工汇总，验证医药行业特有的“商业公司流向”数据从采集到洞察的完整路径。

文件格式

列名必填格式校验
商业公司编码是CUS- 开头客户存在且类型为“商业公司”
产品编码是PRD- 开头产品存在（停售产品允许导入历史流向）
月份是YYYY-MM不晚于当前月，且在近 24 个月内
数量是正整数1–9,999,999
金额是非负数字，最多 2 位小数0–999,999,999.99

文件要求：UTF-8 编码（可带 BOM），首行为表头，最大 2MB、2000 行；模板提供 6 条正确行 + 3 条错误行，便于一次验证三类结果。

导入流程

  1. 下载模板 → 上传文件 → 后端解析并逐行校验，返回预览：总行数、可导入、覆盖、错误。
  2. 预览表格展示前 20 行（含行号、状态、错误原因）；可下载完整错误报告（CSV，UTF-8 BOM）。
  3. 点击“确认导入”：正确行写入，错误行跳过；同一“商业公司 + 产品 + 月份”覆盖旧值并计入“覆盖”。
  4. 生成批次记录：批次号 FL-YYYYMMDD-001、文件名、总行数、成功/覆盖/失败数、操作人、时间、状态。
  5. 批次状态：全部成功 → 成功；部分成功 → 部分成功；全部失败 → 失败；处理中不可删除。

批次管理

  • 批次列表按时间倒序，支持查看详情（下载原文件、错误报告）与删除。
  • 删除批次：删除该批次导入且仍归属该批次的流向记录；被后续批次覆盖的记录不删除。二次确认后执行。
  • 同一文件可重复上传，结果一致；覆盖不产生重复记录。
  • 导入失败（格式、编码、超限）时整体拒绝，不写入任何数据，并给出可修正的原因。

流向看板

  • 筛选：月份范围（默认近 6 个月）、产品、商业公司、区域。
  • KPI：流向数量、流向金额、环比、覆盖商业公司数。
  • 图表：月度流向趋势（折线/柱状）、产品 Top 10（横向条）、商业公司 Top 10、区域金额占比。
  • 明细表：月份、商业公司、产品、数量、金额、批次号；支持分页与 CSV 导出。
  • 统计口径：金额按流向记录金额求和，数量按正整数求和；不含订单数据，避免重复计算。

异常

  • 文件非 CSV、编码错误、缺少表头、超过行数/大小限制时整体拒绝并提示。
  • 所有行都失败时不生成可删除批次，仅保留失败报告？决策：生成“失败”批次，保留错误报告与文件名，不写入流向数据。
  • 删除批次时若记录已被覆盖，提示“该批次部分记录已被后续批次覆盖，仅删除归属本批次的记录”。
  • 代表角色访问流向菜单不可见；直接访问路由显示 403。

6.2 金额与日期

  • 所有金额单位为人民币元，存储两位小数，计算采用四舍五入（HALF_UP）；展示千分位。
  • 折扣率以百分比输入（如 10 表示 9 折），参与计算时除以 100。
  • 日期格式 YYYY-MM-DD，时间格式 YYYY-MM-DD HH:mm，时区固定 Asia/Shanghai。
  • 月份格式 YYYY-MM；“本月”以服务器当前时区计算。
  • “今天”指服务器当前日期；签到、回款日期等判断均以此时区为准。

6.3 审批与状态

  • 通用审批原则：提交人不能审批自己的单据；审批人必须拥有对应数据范围。
  • 通过后不可撤销；驳回必须填写原因，原因进入单据时间线与审计日志。
  • 状态只能通过定义的流转路径变更；后端对每次变更校验当前状态，非法流转返回 409。
  • 状态变更后，相关列表、工作台、报表在同一请求完成后即时反映，不做定时缓存。

6.4 列表、导出与空态

  • 分页参数 page 从 1 开始，size 默认 20、最大 100；超出范围时后端纠正为边界值。
  • 列表默认按创建时间倒序；支持排序的列在表头显示箭头，排序参数为字段名 + asc/desc。
  • 空列表与无搜索结果使用不同文案；无权限与不存在使用不同页面，避免泄露数据是否存在。
  • CSV 导出统一 UTF-8 带 BOM、逗号分隔、字段含逗号或换行时加双引号；导出文件名含报表名与日期。

6.5 审计与并发

  • 所有写操作记录审计：操作人、时间、模块、动作、对象、结果、IP、摘要；失败请求记录失败原因。
  • 涉及金额、审批、删除、重置的操作必须二次确认，确认文案包含对象名称与关键金额。
  • 并发修改使用版本号校验；版本不一致时提示“数据已被他人更新，请刷新后重试”，不覆盖他人修改。
  • 提交类按钮在请求期间禁用并显示加载态，防止重复提交。

6.6 附件与文件

  • 拜访附件支持 jpg/jpeg/png/pdf，单个 ≤ 5MB，每条拜访最多 3 个；存储于本地目录 data/uploads。
  • 文件下载需登录且有对应拜访查看权限；文件名使用随机 ID，展示原始文件名。
  • 流向导入原文件与错误报告保存在本地 data/imports，随批次删除一并清理。
  • 本次不实现病毒扫描；演示环境不上传真实敏感文件。

  • 不使用“lorem ipsum”或空白占位图；无数据时提供明确说明与下一步入口。

8.6 工程质量要求

  • 统一响应结构与错误码：参数错误 400、未登录 401、无权限 403、不存在 404、状态冲突 409、服务异常 500；前端按类型提示。
  • 所有金额、状态流转、权限判断在后端完成；前端只做展示与即时校验，不作为安全边界。
  • 核心规则单测覆盖：订单金额计算、拜访/订单状态机、数据范围过滤、审批人不能自审、回款超额拦截。
  • 种子数据生成幂等：重复执行不会产生重复数据；重置在同一事务内完成，失败回滚。
  • 前端构建无 TypeScript 错误、无控制台报错；关键列表与表单具备加载态、空态与错误态。
