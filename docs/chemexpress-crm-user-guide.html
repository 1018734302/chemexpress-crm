01快速开始

系统由 Java 后端与 Vue 前端组成，数据存储在本地 H2 文件数据库，不需要安装 MySQL、Redis 或任何外部服务。

1.1 启动系统

在项目根目录执行一条命令即可（首次会自动打包前端依赖并启动两个服务）：

powershell -ExecutionPolicy Bypass -File c:\trae\医药CRM\scripts\start.ps1
  • 后端：http://localhost:8080，API 前缀 /api/v1。
  • 前端：http://localhost:5173，浏览器访问这个地址。
  • 数据库：data/crm.mv.db，首次启动自动建表并生成演示数据。
手动启动：后端运行 java -jar backend\target\chemexpress-crm-0.2.0.jar，前端在 frontend 目录运行 npm run dev，然后打开 http://localhost:5173。

1.2 登录

  1. 打开 http://localhost:5173，未登录会自动进入登录页。
  2. 点击演示账号卡片（如「陈晨 / mr.chen」）自动填入账号与密码。
  3. 点击 登录，成功后进入工作台。

02界面与角色

登录后进入统一工作区：左侧是导航，顶部是页面标题、日期与当前用户菜单。

左侧导航

  • 工作台：角色化指标与待办。
  • 客户管理：客户档案、联系人与转交。
  • 拜访管理：计划、签到、记录与审批。
  • 订单管理：订单、发货与回款。
  • 产品中心：只读产品资料。

右上角用户菜单

  • 显示当前姓名、角色与区域。
  • 管理员可见 演示数据重置。
  • 所有角色可见 退出登录。
提示：菜单与操作按钮会随角色变化，看不到某个按钮通常是因为当前角色无权限。

03工作台

工作台是登录后的首页，按角色展示不同的 KPI、趋势图与待办入口。

3.1 页面组成

  • KPI 卡片：代表看个人业绩与待办；经理看区域业绩与待审批；运营看发货、待回款与本月回款。
  • 近 6 个月销售趋势：按发货时间统计已发货与已完成订单金额。
  • 客户结构：当前数据范围内医院、连锁药店、单体药店、商业公司的数量占比。
  • 今日拜访 / 最近订单：代表与经理看今日拜访，运营与管理员看最近订单。
  • 最近动态：运营与管理员可见跨模块操作记录。

3.2 快捷入口

右上角按钮随角色出现：新建客户（代表/经理）、新建拜访（代表）、新建订单（代表/运营）。点击「查看全部」可跳转到对应列表。

04客户管理

客户是拜访与订单的起点。代表只能看到本人客户，经理看到本区域客户，管理员与运营看到全量客户。

4.1 新建客户

  1. 进入 客户管理，点击右上角 新建客户。
  2. 填写客户名称、客户类型、等级、区域、详细地址等；A 级客户必须填写大于 0 的年采购潜力。
  3. 代表创建时负责人默认为本人；经理创建时需要选择同区域的负责代表。
  4. 点击 保存，系统自动生成 CUS- 编号并刷新列表。
规则：同一区域内「客户名称 + 客户类型」不可重复；客户类型创建后不可修改；只有地区经理可以标记客户为「已流失」，且必须填写至少 5 个字的流失原因。

4.2 列表操作

操作谁可以操作说明
查看有数据权限的角色进入客户详情，查看档案、联系人与历史拜访/订单
编辑负责代表、本区域经理修改客户基本信息；客户类型不可改
转交地区经理、管理员只能转交给同区域的医药代表
删除负责代表、经理、管理员客户存在拜访或订单时不能删除

4.3 客户详情

点击客户名称或「查看」进入详情页，页面分为三部分：

  • 客户档案：类型、等级、年采购潜力、来源、标签、地址、备注与最近拜访日期。
  • 联系人页签：新增、编辑、删除联系人；首位联系人为主联系人；被拜访记录引用的联系人不能删除。
  • 拜访记录 / 订单记录页签：点击任意行可直接打开对应详情。

右上角提供 编辑客户、转交、新建拜访、新建订单 快捷按钮，创建时会自动带入当前客户。

示例：用 mr.chen 打开「上海示范第一医院」，在联系人页签新增一位「药剂科主任」，再到拜访页签点击某条记录，即可看到该客户完整的历史跟进。

05拜访管理

拜访遵循「计划 → 签到 → 提交记录 → 审批」的闭环，每一步都会写入操作时间线。

计划中代表创建计划，可改期或取消
→
已签到拜访当日签到，模拟定位距离
→
待审批提交结果、反馈、产品与下一步
→
已通过经理审批，计入业绩与最近拜访

审批不通过时进入「已驳回」，代表修改后可重新提交；计划中或已签到的拜访可以取消。

5.1 新建拜访计划（仅医药代表）

  1. 进入 拜访管理，点击 新建拜访。
  2. 选择拜访客户与联系人；已流失客户不可选择。
  3. 选择拜访日期（今天起 30 天内）与拜访目的，填写备注。
  4. 点击 创建计划，系统生成 VIS- 编号并进入详情页。
重复拦截：同一客户在同一天只允许存在一条未结束的拜访。若提示已存在，请打开原拜访继续操作或先取消。

5.2 签到

打开拜访详情，点击右上角 签到。签到成功后状态变为「已签到」，并记录签到时间与模拟定位距离（60 - 180 米）。

签到按钮不出现？只有拜访负责人、拜访日期为今天、且状态为「计划中」时才可签到。其他情况按钮会隐藏。

5.3 提交拜访记录

状态为「已签到」或「已驳回」时，点击 提交拜访记录 / 重新提交记录，填写：

  • 拜访结果：成功、部分达成、未达成。
  • 客户反馈：10 - 1000 字，记录客户原话与关注点。
  • 下一步计划：5 - 500 字，明确后续动作与时间。
  • 关联产品：至少选择一个在售产品。

5.4 审批、驳回与取消

动作操作人条件结果
审批通过本区域地区经理拜访状态为待审批，且不是自己提交状态变为已通过，客户最近拜访日期更新
驳回本区域地区经理填写至少 5 个字的原因状态变为已驳回，代表可修改后重提
取消拜访拜访负责人状态为计划中或已签到，填写原因状态变为已取消，释放当天重复限制
操作路径：用 mr.chen 创建并签到拜访 → 提交记录；退出后用 dsm.east 登录，在拜访详情中审批通过或驳回。

06订单管理

订单覆盖「草稿 → 待审批 → 待发货 → 已发货 → 已完成」全流程，并支持驳回、取消与回款登记。

草稿代表编辑，可删除
→
待审批提交后进入经理审批
→
待发货审批通过，等待运营发货
→
已发货登记物流，等待回款
→
已完成累计回款等于订单金额自动结案

6.1 新建订单

  1. 进入 订单管理，点击 新建订单。
  2. 选择下单客户（仅「合作中」客户可下单），按需填写期望发货日期、收货地址与备注。
  3. 点击 添加产品，选择产品后填写数量与折扣；折扣单位为百分比，0 表示无折扣。
  4. 确认订单总额：单价 × 数量 ×（1 - 折扣 ÷ 100），系统保留两位小数。
  5. 点击 保存草稿 稍后继续，或点击 保存并提交 直接进入审批。
下单限制：客户必须处于合作中；同一产品不能重复添加；数量至少为 1；单价至少 0.01 元；只能选择在售产品。

6.2 编辑、提交与删除

  • 草稿或已驳回的订单可以编辑并重新提交。
  • 只有草稿可以删除；已提交的订单请使用「取消订单」。
  • 代表只能编辑本人创建的订单；运营可编辑全量订单的草稿。

6.3 审批、发货与回款

动作操作人条件与填写项结果
审批通过dsm.*订单为待审批，且不是自己提交进入待发货
驳回dsm.*填写至少 5 个字的原因进入已驳回，可修改后重提
登记发货ops.zhou订单为待发货；填写物流公司与 6 - 30 位物流单号进入已发货，记录发货时间
登记回款ops.zhou订单为已发货；金额不超过未回款余额；日期不晚于今天累计回款不足时仍为已发货；达到订单金额自动已完成
完整订单链路：mr.chen 创建订单并提交 → dsm.east 审批通过 → ops.zhou 登记发货 → ops.zhou 登记回款（可分多次，最后一次使余额归零，订单自动完成）。

6.4 取消订单

草稿、待审批、待发货状态可以取消，必须填写至少 5 个字的原因。已有回款记录的订单不能取消；已发货订单请通过回款流程正常结案。

07产品中心

产品资料为只读数据，用于拜访关联与订单下单。

  • 支持按商品名、通用名、产品编码搜索，并按在售/停售筛选。
  • 列表展示产品编码、商品名、通用名、规格、剂型、医保类型、参考单价、状态与适应症。
  • 停售产品不会出现在拜访关联与订单产品选择中。
说明：MVP 不提供产品维护入口；产品数据由演示种子生成，数量 12 个。

08演示数据重置

管理员可以一键清空业务数据并重新生成全套演示数据，适合反复自测或演示前恢复初始状态。

  1. 使用 admin 登录，点击右上角用户头像/姓名，选择 演示数据重置。
  2. 在弹窗中输入大写 RESET 并确认。
  3. 系统清空客户、联系人、拜访、订单、回款与动态，重新播种演示数据，并递增数据版本。
  4. 所有已登录会话立即失效，需要重新登录；重新登录后管理员姓名仍为「谢震宇」。
注意：重置会删除你自测时新增的全部数据，且不可恢复；确认文字必须严格为 RESET。
重建数据库：如需连数据库文件一起重建，可停止后端后删除 data/crm.mv.db，再次启动会自动建表并生成演示数据。

10常见问题

Q1：为什么看不到「新建拜访」按钮？

只有 医药代表（MR） 可以创建拜访计划，且按钮只在拜访列表页出现；经理、运营、管理员均不可创建。

Q2：为什么签到按钮不出现？

必须同时满足：你是该拜访的负责人、拜访日期是今天、状态为「计划中」。日期未到、状态已签到或已提交时不会显示。

Q3：提示「该客户当天已有未结束的拜访」怎么办？

说明同一客户今天已有一条计划中/已签到/待审批的拜访。请从列表打开原拜访继续操作，或先取消原拜访再新建。

Q4：为什么客户无法下单？

订单只能选择「合作中」客户。已暂停或已流失客户不会出现在下单客户下拉中，请先在客户详情调整状态（需经理权限）。

Q5：为什么订单没有「审批通过 / 驳回」按钮？

审批仅对 本区域地区经理 开放，且订单必须处于「待审批」；同时系统禁止审批自己提交的订单。

Q6：回款金额为什么不能输入更大的数？

单次回款不能超过当前未回款余额。可多次登记，累计达到订单金额时订单自动变为「已完成」。

Q7：删除客户失败怎么办？

客户存在关联的拜访或订单时禁止删除。可改为将客户标记为「已流失」（经理权限，需填写原因），保留历史数据。

Q8：重置时提示确认文字错误？

确认框必须输入大写 RESET，不能带空格或其他字符。

Q9：重置后为什么被踢回登录页？

这是预期行为：重置会递增数据版本，所有旧 JWT 立即失效。重新登录即可看到全新的演示数据。

Q10：端口被占用、页面打不开？

确认 8080 与 5173 未被其他程序占用；关闭占用进程后重新执行启动脚本。若前端启动但接口报错，请确认后端日志出现 Started CrmApplication。

Q11：数据保存在哪里？会丢吗？

数据保存在项目根目录 data/crm.mv.db，重启不丢；执行重置或删除该文件会恢复初始演示数据。

11规则速查

以下是系统内置的关键校验，遇到提示时可对照排查。

11.1 客户

规则说明
名称长度2 - 60 个字符
唯一性同区域「客户名称 + 客户类型」不可重复
类型创建后不可修改
A 级客户年采购潜力必填且大于 0
流失仅地区经理可操作，需填写至少 5 个字的流失原因
转交只能转交同区域医药代表
删除存在拜访或订单时不可删除

11.2 拜访

规则说明
创建人仅医药代表
日期范围今天起 30 天内
重复限制同一客户同一天只能有一条未结束拜访
签到仅负责人、当日、计划中状态
提交内容客户反馈 10 - 1000 字；下一步 5 - 500 字；至少 1 个产品
审批本区域经理；不能审批本人提交的记录
驳回原因至少 5 个字；代表可修改后重新提交
取消计划中或已签到状态，需填写原因

11.3 订单

规则说明
客户状态仅「合作中」客户可下单
产品仅售在售产品；同一订单产品不可重复；数量 ≥ 1；单价 ≥ 0.01
金额单价 × 数量 ×（1 - 折扣 ÷ 100），保留两位小数
编辑仅草稿或已驳回
删除仅草稿
发货仅运营；物流单号 6 - 30 位字母/数字/短横线
回款仅运营；不超过未回款余额；全额回款自动完成
取消草稿/待审批/待发货；需原因；已有回款不可取消

11.4 状态流转

拜访

计划中 → 已签到 → 待审批 → 已通过

待审批 → 已驳回 → 重新提交 → 待审批

计划中 / 已签到 → 已取消

订单

草稿 → 待审批 → 待发货 → 已发货 → 已完成

待审批 → 已驳回 → 重新提交 → 待审批

草稿 / 待审批 / 待发货 → 已取消
